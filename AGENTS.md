# AGENTS.md

Factual: self-hosted, multi-user budgeting + expense splitting (envelope budgets fed from a pool, credit card statements, savings goals, loans, schedules, splitting between friends and groups, a Vim-style transaction editor). Go API + PostgreSQL + TanStack Start (React, SPA mode) monorepo. UI text is Traditional Chinese (zh-TW). Current phase: Phase 2, personal budgeting (M4 Account register and `:w` done; M5 Slash blocks skipped, ADR-077; M6 Envelopes done; M7 Deployment and M9 Schedules built, waiting for the owner's use to be done; next milestone M8 Credit card statements); roadmap and milestones in `docs/PROJECT_BRIEF.md`. Do not start splitting (Phase 4) or Phase 5 items yet.

## Map
- `apps/api` Go module `factual/apps/api` (echo, oapi-codegen, sqlc on pgx/v5, goose).
- `apps/web` TanStack Start in SPA mode (pnpm workspace member): React 19 + React Compiler, Tailwind, shadcn/ui (Radix), TanStack Query, openapi-fetch.
- `Dockerfile` (repo root) builds the one image; `deploy/` holds the production `docker-compose.yml` and `.env.example`; `docs/DEPLOYMENT.md` documents running, backing up and upgrading it (ADR-083).
- `docs/PROJECT_BRIEF.md` goal, phases, milestones and what is out of scope.
- `docs/DECISIONS.md` the decisions (ADRs) behind the architecture and the ledger model; read the relevant ones before changing either.

## Commands (run from repo root)
- Tasks are mise tasks: repo-wide in `mise.toml`, per project in `apps/api/mise.toml` and `apps/web/mise.toml` (`mise run //apps/api:test`). `mise tasks ls --all` lists them.
- `mise run setup` install tools/deps and enable git hooks (`.githooks` -> lefthook).
- `mise run dev` opens the dekit console (`dekit.yaml`: db, API :8080 with air, web :3000); `mise run dev:down` stops a detached stack. Non-interactive: `dekit up`, `dekit ls`, `dekit down` (don't pipe `dekit up`: the runner keeps the pipe open).
- `mise run gen` regenerates oapi-codegen + sqlc + web API types.
- `mise run check` lint + format check + typecheck + test + build.
- `mise run //apps/api:test:db` then `//apps/api:test:integration` runs the DB integration tests against the local container (database `factual_test`, wiped by the tests). They include the login and OIDC flows against a fake identity provider (`internal/server/auth_test.go`).
- `mise run build` builds one binary with the web app embedded (`apps/api/bin/factual`); `mise run docker:build` builds the image `factual:latest`.
- The first start creates the admin from `FACTUAL_BOOTSTRAP_ADMIN_*` (dev values in `apps/api/mise.toml`).

## Conventions
- API is spec-first: edit `apps/api/api/openapi.yaml`, run `mise run gen`, implement the generated method on the owning domain's `Handlers` (embedded into `internal/server`, so two domains implementing one operation do not compile). Web calls go through `apps/web/src/lib/api.ts` (`api` / `$api`), never hand-written response types.
- Operations inside a budget (paths with `{budgetId}`) also declare `x-budget: read | write | manage` (ADR-057); the server checks membership and role, so handlers never do, and every query in them is scoped by the path's budget id. Amounts are integers in the budget's minor unit (`minorUnits`, ADR-056); format and parse them with `apps/web/src/lib/money.ts`.
- UI wording (ADR-062): an envelope is called 預算 in the interface (the category's budget); never show 信封. Expense categories pool by default (ADR-061).
- Every operation declares exactly one `x-auth`: `public`, `authenticated` or `admin` (instance admin); the API does not start otherwise. The session middleware puts the caller in the context: read it with `reqctx.Caller(ctx)`, never parse cookies or check `IsAdmin` in handlers. Browser-navigated endpoints (the OIDC flow) answer with redirects carrying `?error=<code>`, not JSON.
- Never hand-edit generated files: `internal/api/api.gen.go`, sqlc output (`internal/domain/*/internal/db/`), `apps/web/src/lib/api.gen.ts`, `apps/web/src/routeTree.gen.ts`.
- Schema changes are goose SQL migrations in `apps/api/db/migrations` (`mise run //apps/api:db:new <name>`); never edit an applied migration. They are embedded in the binary and applied on startup; sqlc reads the same directory as its schema. Wrap function bodies in `-- +goose StatementBegin/End`.
- Domains live in `apps/api/internal/domain/<name>` with their SQL in `queries/*.sql`, generated into their private `internal/db` (one `sqlc.yaml` entry per domain). Shared helpers in `internal/shared`.
- Handlers return `apperr.New(status, code, message)` for expected failures (`apperr.FromDB` maps not-found/duplicate/FK/check errors); everything is rendered as the `Error` envelope.
- Config is environment variables (`FACTUAL_*`, `internal/config`); local dev values come from `apps/api/mise.toml`. A new variable also goes into the table of `docs/DEPLOYMENT.md` (and `deploy/` when Compose must pass it).
- The binary serves the web app from `internal/webui` (ADR-083): the build copies `apps/web/dist/client` into `internal/webui/static`, which is git-ignored except its placeholder; never commit the copy. Every path outside `/api` is the app (`internal/server/web.go`).
- Authorization is plain Go (role -> permission map plus SQL scoping by `budget_id`); no casbin.
- Login (ADR-014, ADR-046..051): sessions are rows in `sessions` keyed by the SHA-256 of the cookie token; CSRF protection is SameSite=Lax plus the cross-site guard, so keep state changes off GET. OIDC identities are matched by (provider, subject), never by email, and only log in after their owner linked them; do not add auto-provisioning or email matching. Client secrets are sealed with `internal/secretbox` and never returned by the API.
- Never put real secrets in the repo: the values in `apps/api/mise.toml` are local-development defaults only.
- When a milestone is done, mark it *(done, ADR-…)* in `docs/PROJECT_BRIEF.md` and update the current phase above.
- Record architectural changes in `docs/DECISIONS.md`: append a new ADR, never rewrite an old one (a replacing entry says which it supersedes); drop the *(planned)* mark when a planned decision is implemented.
- Web UI: shadcn/ui components live in `apps/web/src/components/ui` (add with `pnpm dlx shadcn@latest add <name>` from `apps/web`; vendored, excluded from oxlint). Never run `tanstack add`: it regenerates the whole template over modified files. Pages under `src/routes/_app` need a session (`beforeLoad` in `_app.tsx`); show API errors with `apiErrorMessage()` and add a zh-TW message to `src/lib/apiError.ts` for every new error code.
- Styling (ADR-053..055): use the theme tokens (`bg-background`, `text-muted-foreground`, `border-rule`, `bg-kraft`, `text-positive`, `text-destructive`...), never raw colours, and check both themes (dark is the default). Money is shown with `.amount` (monospaced tabular figures). Settings pages use `PageHeader` and `Section` from `src/components/section.tsx`; give each page `staticData: { crumb, section? }` for the status line.
- The account register (ADR-063..075): row and split logic lives in `apps/web/src/lib/register.ts`, key mappings in `src/lib/keymap.ts`; both are tested with plain node (`pnpm test`) and stay free of React. Editors take keys through `useKeyFeed` (`src/components/register/use-key-feed.ts`) with their pane name, so user mappings (global and `autocmd FileType <pane>`) apply; the sidebar uses `useListKeys`; name keys as Vim does (`<CR>`, `<C-s>`). A register shows one account or a group (`RegisterView`); rows are keyed by transaction and account (`Row.key`), and edits go through `syncRows` so every row of a transaction stays in step; changes to several rows go through `patchRows` (one undo step) and act per transaction (`transactionKeys`), as visual mode does. Mark focusable regions with `data-pane` (and key-reading editors with `data-editor`) for the window commands `<C-w>h/j/k/l` (`src/lib/panes.ts`); do not bind keys like Ctrl-h by default, users map them. The grid (`src/components/register/register-grid.tsx`) keeps one cursor overlay and one cell editor (ADR-045); saving goes only through the batch endpoint. New keys go into the `?` reference (`src/components/register/key-help.tsx`), not the hint line.
- The budget page (ADR-078..082): the lines (expense and income sections) of one to three months are built in `apps/web/src/lib/budget-month.ts` (`pageMonths` keeps every month's lines identical, so a row index means one category in all of them) (pure, tested with `pnpm test`), the grid is `src/components/budget/budget-grid.tsx` (pane `budget`, keys in `budgetKeys` of `key-help.tsx`); allocations save at once through `PUT .../months/{month}/allocations`, never through drafts, and every month query (`['budget-month', budgetId]`) is reloaded after a change because later months carry its balances. Categories are edited only on this page (there is no category page): changes go through `src/components/budget/category-api.ts` (several at once through `category-tree.ts`), and every change is a `Step` with `undo`/`redo` in the grid's one history. Keys that exist in the register (`yy`, `dd`, `p`, `V`, `gv`, counts) must work the same way here; `y` keeps whole lines (categories and allocations), `d`/`p` act on the cursor's column, and anything touching an allocation uses the cursor's month.
- Schedules (ADR-084..087): rules are typed and shown in `apps/web/src/lib/schedule-rule.ts` (one way of showing a rule, `describeRule`, which the parser reads back; the rule editor's form is `rule-form.ts`), the page's lines in `src/lib/schedules.ts`, the grid in `src/components/schedules/schedule-grid.tsx` (pane `schedules`, keys in `scheduleKeys`); all pure parts are tested with `pnpm test`. The browser only expands rules for previews; the server expands them with rrule-go (`internal/domain/ledger/rules.go`) and is what posts (`RunScheduler`, idempotent through `(schedule_id, occurrence_date)`), so keep the client's expander to the RRULE subset the parser writes. Registers show `GET .../schedules/upcoming` as 預定 rows (`plannedRows` in `register.ts`: an id derived from schedule and occurrence, not in the running balance; saving one sends `occurrence`). Targets come with the month response; only `:fill` turns them into allocations, nothing is allocated by itself. Days off come from the admin's import of the government calendar (`internal/domain/calendar`), weekends for years without one.
- Use pnpm, not npm/yarn. Web is linted with oxlint (`oxlint.config.ts`, type-aware, extends `@tanstack/oxlint-config`) and formatted with oxfmt (`oxfmt.config.ts`, extends `@tanstack/oxfmt-config`); Go with golangci-lint. lefthook enforces both on commit.

## Ledger model (ADR-020..033; details in the comments of the first migration)
- Money is `bigint` minor units; entry amounts are the change in the account's balance.
- A transaction has entries `(account, category?, amount)`. The database rejects a transaction unless its entries on on-budget accounts without a category sum to zero; entries on off-budget accounts (loans, investments) never carry a category. This guarantees: on-budget total = pool + all envelope balances.
- Income goes to the pool, not to a month; `allocations` move it into envelopes. Envelope balances are cumulative sums (no month close). Credit card reserve and goal progress are derived, never stored.
